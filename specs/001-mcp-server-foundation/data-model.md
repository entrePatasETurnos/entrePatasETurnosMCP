# Data Model: EntrePatasETurnos MCP Server Foundation

The MCP server owns no domain data (Principle I). It owns only **configuration**, **auth and session
state** (kept in Redis), and **tool input and output models**. Domain entities such as pets,
bookings and appointments are views of API responses, cut down to what each tool needs (FR-014).

## 1. Configuration (`Settings`, environment variables with prefix `MCP_`)

| Variable | Type | Required | Default | Secret | Notes |
|---|---|---|---|---|---|
| `MCP_API_BASE_URL` | URL | yes | — | no | e.g. `https://api.entrepataseturnos.com.br`. All paths are `/v1/...`. |
| `MCP_API_TIMEOUT_SECONDS` | float, >0 and ≤60 | no | `10` | no | Read timeout. Connect timeout is fixed at 3 s. |
| `MCP_PUBLIC_BASE_URL` | https URL | yes | — | no | Public URL of this server. Used as the OAuth issuer and to build the Google callback. |
| `MCP_GOOGLE_CLIENT_ID` | str | yes | — | no | Must equal the API's configured Google audience. |
| `MCP_GOOGLE_CLIENT_SECRET` | SecretStr | yes | — | **yes** | Secret only. |
| `MCP_REDIS_URL` | SecretStr (URL) | yes | — | **yes** | May contain a password. |
| `MCP_TOKEN_ENCRYPTION_KEY` | SecretStr, base64 of 32 bytes | yes | — | **yes** | AES-256-GCM key for stored API tokens. |
| `MCP_ACCESS_TOKEN_TTL_SECONDS` | int | no | `3600` | no | Lifetime of MCP access tokens. |
| `MCP_HOST` / `MCP_PORT` | str / int | no | `0.0.0.0` / `8000` | no | Listen address and port. |
| `MCP_LOG_LEVEL` | enum | no | `INFO` | no | Log verbosity. |

**Validation at startup**: when a setting is missing or invalid, the server exits with code 2 and
prints `missing/invalid setting: MCP_X`. It never prints values.

## 2. Auth and session state (Redis)

All keys share the prefix `epet:mcp:`. Token keys store a hash (`sha256(token)` in hex), never the
token itself.

### APISession, key `session:{sid}`

- `sid` is a random 128-bit id generated by the MCP server.

| Field | Type | Notes |
|---|---|---|
| `api_session_id` | int/str | `sessionId` from the API. |
| `user_id` | int | The `sub` value from the API. Never accepted from tool input. |
| `access_token_enc` | bytes | AES-GCM ciphertext with its nonce. |
| `access_expires_at` | datetime | From `accessTokenExpiresAt`. |
| `refresh_token_enc` | bytes | AES-GCM ciphertext. Rotated on each refresh. |
| `refresh_expires_at` | datetime | The record's TTL is set to this time. |
| `created_at` | datetime | Creation time. |

**State transitions**:

```text
(none) --google sign-in OK--> ACTIVE
ACTIVE --access token within 60s of expiry, refresh OK--> ACTIVE (tokens rotated)
ACTIVE --refresh 401 / refresh expired--> DELETED  (tool returns sign_in_required)
ACTIVE --sign_out / revoke--> DELETED (API DELETE /v1/auth/sessions/{id} attempted first)
```

**Refresh lock**: key `session:{sid}:lock`, created with `SET NX PX 10000`.

### OAuthClient, key `client:{client_id}`

Holds the RFC 7591 registration (`OAuthClientInformationFull`): redirect URIs, name, grant types.
It has no TTL.

### PendingAuthorization, key `pending:{state}`

- TTL is 600 seconds.
- Fields: `client_id`, `redirect_uri`, `code_challenge`, `scopes`, `client_state`,
  `google_code_verifier`.
- It is consumed exactly once, on the Google callback.

### AuthorizationCode, key `code:{hash}`

- TTL is 300 seconds. The code is single-use and deleted on exchange.
- Fields: `client_id`, `redirect_uri`, `code_challenge`, `scopes`, `sid`, `expires_at`.

### AccessToken, key `at:{hash}`

- TTL is `MCP_ACCESS_TOKEN_TTL_SECONDS`.
- Fields: `client_id`, `sid`, `scopes`, `expires_at`.

### RefreshToken, key `rt:{hash}`

- TTL ends at `refresh_expires_at` of the session.
- Fields: `client_id`, `sid`, `scopes`.
- It rotates on use: the old key is deleted when the new one is issued.

### Session index, key `session:{sid}:tokens` (a set)

Holds the hashes of every access and refresh token issued for the session. Sign-out and revocation
use it to delete them all.

## 3. Tool input models (validation per FR-010)

Shared types:

- `OffsetDateTime`: an ISO-8601 string. **It must carry an explicit offset**, for example
  `2026-12-01T14:00:00-03:00`. Strings without an offset are rejected.
- `LocalDate`: `YYYY-MM-DD`.
- `PositiveId`: an integer ≥ 1.
- `Page`: `page` ≥ 0 (default 0) and `size` from 1 to 100 (default 20).

| Model | Fields and rules |
|---|---|
| `RegisterAccountInput` | `name`: str, 1–200 characters, not blank after trim. `email`: email format. `cpf`: 11 digits after removing `.` and `-`, valid check digits, not all the same digit. `password`: str of at least 8 characters, not trimmed, never logged or echoed. `user_confirmed`: bool, required to be true when the client lacks elicitation. |
| `ListPetsInput` | `Page`. |
| `FreeDatesInput` | `from_date`: LocalDate, optional, defaults to today, must not be in the past. `to_date`: LocalDate, optional. The range from `from_date` to `to_date` is at most 366 days. `pets`: 1–50, default 1. `nights`: 1–90, default 1. |
| `AvailabilityInput` | `from_`, `to`: OffsetDateTime, both required. `to` > `from_`, and the span is at most 366 days. |
| `BookingInput` (create/update) | `pet_ids`: 1–50 unique PositiveIds. `check_in`, `check_out`: OffsetDateTime. `check_out` > `check_in`, and `check_in` must not be in the past. Update also takes `booking_id`: PositiveId. |
| `BookingListInput` | `status`: optional, one of `registered`, `approved`, `denied`, `completed`. `from_`, `to`: optional OffsetDateTime. Plus `Page`. |
| `BookingRefInput` | `booking_id`: PositiveId. |
| `BathSlotsInput` | `date`: LocalDate. |
| `AppointmentInput` (create/update) | `pet_id`: PositiveId. `starts_at`: OffsetDateTime, not in the past. Update also takes `appointment_id`. |
| `AppointmentListInput` / `AppointmentRefInput` | Same rules as the booking equivalents. |

**Forbidden fields**: no input model has `user_id`, `owner_id`, `account_id` or `role`, and every
model sets `extra="forbid"`, so unknown fields are rejected (FR-007).

## 4. Tool output models (trimmed views)

`_links`, `ownerId`, `ownerName`, reviewer and completer ids, and `createdAt`/`updatedAt` are
dropped unless the table lists them.

| Model | Fields kept |
|---|---|
| `PetSummary` | `id`, `name`, `species`, `gender`, `age`. |
| `PetPage` / `BookingPage` / `AppointmentPage` | `items`, `page {number, size, total_items, total_pages}`. |
| `FreeDates` | `from`, `to`, `pets`, `nights`, `first_fit`, `days[{date, free, fits}]`. |
| `Availability` | `from`, `to`, `capacity`, `intervals[{start, end, available}]`. |
| `Booking` | `id`, `status`, `check_in`, `check_out`, `nights`, `pets[{id, name}]`, `denial_reason` (only when denied). |
| `BathDay` | `date`, `open`, `duration`, `slots[{time, starts_at, ends_at, available}]`. |
| `BathAppointment` | `id`, `status`, `starts_at`, `ends_at`, `pet {id, name}`, `denial_reason` (only when denied). |
| `RegistrationResult` | `email`, `status`, plus a `next_step` message: verify the email, and note that password accounts cannot yet sign in through the assistant. |
| `CancelResult` | `cancelled: true`, plus `booking_id` or `appointment_id`. |

## 5. Error payload (`ToolError` content)

```json
{ "error_code": "insufficient_capacity", "message": "...", "http_status": 409,
  "fields": { "petIds": "..." }, "details": { "pet_ids": [3, 5] } }
```

- `error_code` is the API's `error` value unchanged, or one of the server's own codes:
  - `validation_error`
  - `sign_in_required`
  - `cancelled_by_user`
  - `confirmation_required`
  - `upstream_timeout`
  - `outcome_unknown`
  - `upstream_unavailable`
  - `upstream_invalid_response`
  - `session_store_unavailable`
- `fields` and `details` appear only when they have content.
